## Checked and found sound
- **Service-role key**: not in `.next/static`, not in the APK; only server code reads it. No secret (`LINK_SIGNING_SECRET`, `INGEST_API_KEY`, `SMSGATE_WEBHOOK_SECRET`, `DEMO_USER_PASSWORD`) appears in the client bundle; the only `NEXT_PUBLIC_*` values are the Supabase URL, anon key and app URL.
- **RLS with the anon key**: every public table has RLS on; anon reads `[]` everywhere, `sms_outbox`/`eta_cache` are not granted at all, anon INSERT → 401, `current_role_name()` not executable by anon. A hospital JWT cannot update incidents (403), cannot promote its own profile (no UPDATE grant), cannot read reports, audit, outbox or other hospitals' pre-alerts.
- **Forged webhook**: no signature → 401, wrong signature → 401 (HMAC-SHA256, constant-time compare, ±window timestamp). Secrets have minimum lengths in `env.ts`, so an empty secret cannot sign.
- **IDOR**: `/api/incidents/[id]` GET/PATCH → 401 without a session or for a role-less account, 403 for a hospital. Hospital A → hospital B pre-alerts/status → 403; ACK of another facility's pre-alert → 403 (`ackPrealert` checks the row's hospital). `/hospital/[id]` page redirects a hospital to its own facility.
- **Capability links**: id swapped or `k` altered → the "not valid" page (no data); the crew link's expiry is inside the signature (forged → 404 "not valid", genuine but late → 410); covered by e2e.
- **XSS**: no free-text field on the witness or crew forms (enums and integers, zod `.strict()`, 16 KiB body cap). Raw SMS text, override and cancel reasons render through React (escaped). The only `dangerouslySetInnerHTML` are QR SVGs generated server-side from URLs we build.
- **PII in logs**: the app has no `console.*` logging. Phone numbers are stored only where needed (`sms_outbox`, the reply-to of a report) and hashed for rate limiting; webhook capture (`SMSGATE_CAPTURE_DIR`) is off in production and its folder is git-ignored; no real number is tracked in git (fixtures use `+213555000xxx`).
